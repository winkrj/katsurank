# 카츠랭 현재 개발 상태

- 기준일: 2026-09-01
- 목적: 완료된 구현, 브랜치별 차이, V1 출시 전에 남은 작업을 한곳에서 확인한다.

## 요약

카츠랭은 제품 정책, 백엔드 핵심 API, 지도 중심 반응형 UI, 운영 배포 경험까지 구현됐다. 랭킹
polling 병목을 측정한 뒤 TOP 20 캐시와 SSE 스냅샷 전파도 개발했다. 현재 남은 핵심은 서로 다른
브랜치에 있는 최신 프론트와 백엔드를 통합하고 SSE 이벤트 이름·데이터 범위를 맞추며, 화면에 남은
데모성 상세 정보를 제거한 뒤 재검증하는 일이다.

## 반드시 해결할 출시 차이

### 이벤트 이름

현재 최신 프론트와 백엔드의 SSE 이벤트 이름이 다르다.

```text
origin/main frontend: ranking-snapshot 구독
feat/v1-backend-completion backend: vote-changed 전송
```

payload는 양쪽 모두 `version`, `changedAt`, `generatedAt`, `items`를 포함한 TOP 20 스냅샷을 전제로
한다. V1 통합 시 이벤트 이름을 백엔드 계약인 `vote-changed`로 맞추고 브라우저에서 실제 재정렬까지
확인해야 한다.

### 랭킹 결과 범위

데스크톱 랭킹 패널의 REST 조회 한도는 TOP 100이지만 SSE payload는 TOP 20이다. 현재 프론트 hook은
SSE snapshot으로 목록 cache를 교체하므로, 첫 이벤트 뒤 TOP 100 목록이 20개로 줄면서 `total`·`limit`와
내용이 어긋날 수 있다. V1 통합 전에 아래 중 하나를 제품·API 계약으로 확정해야 한다.

- 화면의 실시간 목록 자체를 TOP 20으로 통일한다.
- SSE 수신 시 TOP 20만 교체하고 기존 21~100은 보존·재정렬한다.
- SSE는 변경 신호로만 쓰고 기존 REST 목록을 다시 조회한다.

### 상세 화면의 데모성 정보

최신 `origin/main` 상세 화면에는 백엔드 데이터가 아닌 계산형 주간 추이, 가짜 댓글, 고정 전화번호와
이미지가 실제 정보처럼 표시된다. 댓글·리뷰·주간 통계는 V1 제외 범위이므로 공개 전 제거하거나 명확한
비활성 placeholder로 바꾸고, 전화·링크 등 제공 가능한 값만 실제 상세 DTO에서 사용해야 한다.

## 의도적으로 V1에서 제외한 범위

아래 기능은 출시 범위가 아니다. 현재 화면에 남아 있는 댓글·주간 추이 형태의 데모 표현도 구현 완료로
보지 않으며 공개 전 제거 대상이다.

- 댓글과 리뷰
- 주간 투표 통계·별도 동적 랭킹
- 메뉴·가격·사용자 사진 업로드
- 지역별 독립 랭킹
- 푸시 알림과 WebSocket
- 추천·친구 기능
