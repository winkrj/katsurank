## 1. 한 줄 요약

서울에서 진짜 최고의 돈까스집 단 하나를 가리는 사이트. 카카오 로그인 사용자가 평생 단 한 집에만 투표하고, 더 맛있는 곳을 발견하면 표를 옮길 수 있다. 랭킹은 **서울 단일 랭킹** 하나뿐이며, **서울 1위**가 왕좌다. **표 = 누군가의 1순위라는 진심.**

서비스는 **지도 하나의 화면**으로 존재한다. 탐색·랭킹 확인·검색·투표·가게 등록·내 표 확인까지 전부 이 화면 위에서 끝난다.

## 2. 타겟 사용자

- 서울에서 돈까스 맛집을 찾고 싶은 20~30대
- 별점·리뷰 사이트가 너무 정보가 많고 신뢰가 안 가는 사용자
- "내 인생 돈까스"라는 컨셉에 공감하는 사람들

## 3. 핵심 가치 제안

- **단순함**: 별점 0.5 단위 고민 없음. 표 한 장이 전부.
- **신뢰감**: 표 = 한 사람의 1순위. 별점 100개보다 무거움.
- **단 하나의 왕좌**: 서울 1위 돈까스 단 한 집. 모두가 그 하나의 자리를 두고 표를 던진다.
- **공간감**: 지도 기반으로 후보들을 탐색. 지도는 핀·탐색 용도, 랭킹은 서울 전체 단일.
- **원페이지**: 페이지를 옮겨 다닐 필요가 없다. 지도 위에서 탐색하다가 그 자리에서 바로 투표하고, 그 자리에서 바로 순위가 바뀐다.
- **즉시성**: 누군가 표를 옮기는 순간, 지금 화면을 보고 있는 모든 사람의 랭킹이 그 자리에서 바뀐다. 새로고침이 필요 없다.


## 4. 차별점

| | 기존 서비스 (네이버지도/카카오맵/망고플레이트) | 인생 돈까스 |
|---|---|---|
| 평가 단위 | 별점 (다회 가능) | 1인 1표 (평생) |
| 신호 강도 | 약함 (만족도) | 강함 (1순위) |
| 카테고리 | 전체 음식점 | 돈까스 전용 |
| 핵심 화면 | 검색·리뷰 (다수 페이지) | 지도 원페이지 하나 (탐색+랭킹+투표+검색 통합) |
| 랭킹 단위 | 지역·카테고리별 다수 | 서울 1개 (단 하나의 1위) |
| 갱신 방식 | 새로고침 필요 | 실시간 반영 (누가 투표하든 즉시 보임) |

## 5. 화면 구조 (원페이지)

- **루트(`/`)가 곧 서비스 전체다.** 별도의 랭킹 페이지·지도 페이지·검색 페이지·마이페이지가 없다.
- 화면 중심은 **지도**. 좌측(데스크탑)/하단(모바일)에 **서울 단일 랭킹 패널**이 항상 붙어 있다.
- **가게 상세**: 랭킹 목록·지도 핀·검색 결과 어디서 클릭해도 그 자리에서 상세 화면이 열린다(데스크탑은 좌측 패널이 전환, 모바일은 화면 위로 열림). 별도 URL로 이동하지 않는다.
- **가게 등록**: 랭킹/지도 화면 위에 뜨는 화면으로 처리한다. 검색 → 위치 확인 → 최종 확인 3단계는 유지.
- **공유하기**: 가게 상세에서 공유하면 그 가게가 바로 열리는 링크(`?restaurant=가게ID`)가 생성된다. 링크를 받은 사람은 들어오자마자 지도가 그 가게로 이동하고 상세가 자동으로 열린다.
- **로그인/이용약관/개인정보처리방침**은 예외적으로 별도 화면을 유지한다 (로그인 전에도 접근 가능해야 하는 고지 성격).

## 6. 투표 정책 (확정)

- 카카오 로그인 필수, **1인 1표**
- **표 이동 가능 (A안)**: 새 가게에 투표 시 이전 가게 표는 -1, 새 가게 +1
- 사용자별 **표 이동 히스토리** 마이페이지에 표시
- (V1.1) 가게별 "이번 주 표를 가져온 수" 같은 동적 지표
- **투표는 실시간으로 반영된다**: 누군가 표를 옮기면, 그 순간 화면을 보고 있는 모든 사용자의 랭킹·지도 핀이 자동으로 갱신된다 (새로고침 불필요). 자세한 갱신 방식은 `02_mvp_scope.md` 참조.

## 7. 가게 데이터 정책

- **초기 수동 등록**: 본인이 직접 20곳 등록 (서울 전역, 유명 가게 위주)
- **사용자 추가**: 카카오맵 로컬 API 검색 결과에서 선택
  - 중복 방지: `kakao_place_id` unique (지점별 고유)
  - 카테고리 검증: "돈까스"·"돈가스"·"돈카츠"·"경양식" 키워드 포함 카테고리만 ACTIVE
  - 검증 통과 시 **즉시 ACTIVE** (사전 승인 없음)
- **체인점 = 독립된 가게**: 지점마다 별개로 등록. 본점 구별·병합 안 함. (지도 기반·지점별 맛 차이 때문. 카카오 place_id가 지점을 자동 구분.)
- **폐업·이전 정책 (A+C)**:
  - **폐업(CLOSED) = 박제**: 투표는 막되 기존 표·히스토리는 보존. 랭킹 제외, 마이페이지엔 "폐업한 ○○" 표시.
  - **이전(RELOCATED) = 승계**: 같은 가게의 위치 이동이므로 표를 새 레코드로 이관.
  - 감지는 MVP에서 운영자 수동. 사용자 신고는 V1.1 검토.
  - 데이터는 **hard delete 하지 않음** — 상태로만 관리해 진심의 기록을 보존.

## 8. 어뷰징 방어

- 카카오 로그인 필수 (계정 생성 마찰)
- 1인 1표 (중복 투표 차단)
- (검토) 카카오 가입일 30일 이상만 투표 가능
- (검토) 표 이동 쿨타임 (예: 1시간)
- 가게별 투표 추이 그래프 공개 → 비정상 패턴 시각화

## 10. 비즈니스 / 운영

- **수익 모델**: 없음 (개인 프로젝트, 무료)
- **운영 비용**: 호스팅 무료 티어 + 도메인 약 1.5만원/년
- **컨셉 확장 가능성**: 잘 되면 "인생 라멘", "인생 김밥" 등 카테고리 확장
  - 설계 시 `Restaurant.category` 필드 미리 만들어둠
